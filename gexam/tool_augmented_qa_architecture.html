How a search-enabled assistant can work

A high-level architecture for deciding whether to search, gathering evidence, checking whether it answers the question, and composing a response.

Scope: This is one representative design pattern, not a diagram of any particular product’s private implementation. Real systems vary, and some checks may be done by software around the language model.

Request → evidence → answer

The model can alternate between reasoning and tool use before it returns a final response.

1 · Request
User question“What are the latest rules?” plus conversation context
↓
Input preparationBuilds the model context from the message, relevant history, and available instructions
2 · Decide and retrieve
Language modelInterprets the request and estimates whether its current context is enough
↓ if external facts would help
Tool routerChecks tool availability and routes a structured search request
↓ query
Search serviceFinds pages or other sources and returns results, snippets, and links
3 · Assess evidence
Evidence checksAre the results relevant, recent enough, specific, and consistent?
Source inspectionOpen useful pages; extract text, dates, and source details
Evidence contextSelected information is supplied back to the model
4 · Respond
Language modelUses the question and retrieved context to draft an answer
↓
Answer checksCheck coverage, unsupported claims, and whether citations support key statements
↓
Final responseAnswer with sources or citations when appropriate
Search loop (optional)If key information is missing, stale, or conflicting, the model can issue a narrower query or inspect another source. Tool limits or application rules may stop the loop.

The quality judgment is probabilistic. A model can miss a gap or misread a source, so reliable systems may add source rules, validation code, and limits on tool calls.

What the model contributes

Interprets the request, chooses or formulates a tool call, combines evidence with conversation context, and writes a coherent answer.

What tools contribute

Search retrieves external material. Page readers or databases return content the model did not already have in its prompt.

What application logic can add

Tool permissions, required lookups, timeouts, result formatting, source filters, citation checks, and a maximum number of search steps.

Why this is often called retrieval-augmented generation

Relevant information is retrieved and added to the model’s working context, then the model generates a response using that context. The retrieved pages generally support the current answer; they are not automatically added to the model’s permanent training.
