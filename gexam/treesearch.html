Summary of Tree Search Algorithms

1. Comparison: DFS vs. BFS

Tree traversal typically relies on two foundational approaches: Depth-First Search (DFS) and Breadth-First Search (BFS). They navigate search spaces with opposing core mechanics, leading to completely different resource constraints and ideal use cases.

Feature Depth-First Search (DFS) Breadth-First Search (BFS)
Core Strategy Dives deep down a single path/branch to its terminal end before backtracking. Explores the tree level-by-level, radiating outward from the root node.
Data Structure Uses a Stack (LIFO - Last In, First Out) or recursion. Uses a Queue (FIFO - First In, First Out).
Memory Usage Very Low: Only needs to store the nodes of the single path it is currently walking. Extremely High: Must track all neighbor nodes across an entire layer simultaneously in RAM.
Optimality Not guaranteed to find the shortest path first. Guaranteed to find the shortest path first (in unweighted graphs).

Suitable Problems For Each Approach

  • BFS is best for: Problems requiring the shortest, closest, or fewest moves to a known target. Examples: GPS routing (fewest intersections), social network connectivity (degrees of separation), web crawlers, and flood-fill/broadcasting simulations.
  • DFS is best for: Problems involving deep decision trees where memory is restricted, games requiring long-term future planning, or situations where you need to track an entire complex sequence of events to a definitive end state.

2. Key Concepts & Variations of Depth-First Search

In adversarial game theory and complex problem-solving, traditional DFS is enhanced using the following variations and safety systems:

  • Mini-Max Algorithm: A decision-making framework for two-player, zero-sum games. It maps out a game tree assuming both players will play perfectly. The AI acts as the Maximizer (choosing paths that maximize its score), while the opponent acts as the Minimizer (choosing paths that limit the AI's score).
  • Alpha-Beta (AB) Pruning: An optimization that skips calculating branches that are mathematically proven to be irrelevant. It maintains two values: Alpha (the minimum score the Maximizer is guaranteed) and Beta (the maximum score the Minimizer will allow). If Alpha >= Beta, the branch is "pruned" (cut off) because a rational opponent would never allow the game to go down that path.
  • The Horizon Effect: A fundamental vulnerability where a strict depth limit (e.g., stopping exactly at 10 turns deep) leaves the algorithm blind to massive tactical shifts happening just past its viewing limit (at turn 11 or 12).
  • Quiescence Search: The main fail-safe against the Horizon Effect. When the algorithm hits its maximum depth limit, it evaluates whether the current board position is "unstable" (e.g., active piece trades or checks). If unstable, it extends the search strictly for tactical capture moves until the board becomes "quiet" (stable) before calculating a score.
  • Heuristic Evaluation Functions: Rules used to score the game state when the algorithm cannot reach the end of the match. Beyond counting surviving pieces (material value), a modern function factors in piece mobility, center board control, king safety, and permanent pawn structures (e.g., passed or isolated pawns).
  • Iterative Deepening: A hybrid strategy that manages DFS. Instead of launching a blind search straight to Depth 10, the engine performs separate, complete DFS passes at Depth 1, then Depth 2, then Depth 3, and so on. This ensures a safety-net move is always available if the clock runs out, and it enables near-perfect Move Ordering.
  • The Tightly Correlated Tree Assumption: The core philosophical foundation that makes Iterative Deepening effective. It relies on the reality that games like chess change incrementally (gradually) rather than randomly. Therefore, a high-scoring move found at Depth 9 has an incredibly high probability of remaining a great move at Depth 10, serving as an effective starting branch to achieve immediate Alpha-Beta pruning.
